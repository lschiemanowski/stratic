# Repository-local skills

Repository-local installation makes Stratic’s guidance available alongside the program it describes. Skills are ordinary files under .agents/skills, suitable for committing with the project. The core skill is named stratic; the optional test-first workflow is stratic-tdd. The npm package includes the bundled copies used for installation and later updates, and their guidance uses the installed CLI. Installation does not rewrite project instructions, configure a global agent, or choose a workflow on the user’s behalf.

Installing without optional workflows adds only the core. Selecting TDD adds both the core and its supplement. Repeating installation with identical contents leaves the files unchanged. Existing different files are preserved, including previously installed versions; an explicit update is the operation for bringing recorded installations forward.

A small installation record stores the content hash of each installed SKILL.md. Status compares the local contents, that record, and the current bundle. It distinguishes absent skills, deleted recorded files, unrecorded custom files, locally modified files, unchanged older versions, and current contents. Status does not create files. The record is installation bookkeeping, not evidence that an agent used or correctly followed the skill.

Update considers only recorded skills and compares all selected files before writing. A file unchanged since installation can receive the bundled version. A local edit or deletion stops the operation with the affected paths and the location of the bundled versions, allowing an explicit manual merge. For example, a clean older core is left untouched when an edited TDD skill conflicts in the same update. A manually reconciled file matching the current bundle can be recorded without replacing it. Additional files in skill folders and unrelated skills remain untouched; the installer has no force-overwrite or pruning operation.

Installation accepts only the bundled skill identities and record keys. Symbolic links and unexpected file types at installation directories, skill files, or the record are rejected. These checks keep ordinary installation from following a redirected path outside the selected repository. Files remain ordinary working changes: installation neither stages nor commits them. The installer reports known conflicts before writing; it is not a transaction against concurrent filesystem edits or disk failures.
