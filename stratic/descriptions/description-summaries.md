# Description summaries

A summary gives a short account of a description’s responsibility in bullet points. It helps a reader orient themselves when reading every full description would be burdensome. The bullets state the program’s behavior, important conditions, and boundaries at that description’s level; they do not merely list the topics or children covered by the full text.

The full description supplies the complete account. Its summary preserves the qualifications that matter to understanding its promises, while leaving detailed explanations to the full text. A summary must not introduce a different promise or conceal an important limitation. The coding agent maintains it alongside the description, and a review of changed behavior includes checking that any existing summary still agrees.

Summaries are optional project content stored and versioned with their descriptions. They are prepared during ordinary agent work, rather than generated by the desktop when a reader opens a page. A project can acquire useful summaries gradually; their absence does not make otherwise valid descriptions incomplete or unreadable.

For example, a long description of queue storage could be summarized by its persistence guarantees, the state it retains, and the conditions under which a write succeeds. Those bullets help compare responsibilities quickly; the full account explains how the storage mechanism achieves those guarantees.

A summary belongs to the same description identity and project revision as the full account. It has no independent place in the hierarchy or review authority. The initial model keeps passage-to-code links in the full description, avoiding a second set of links that would need to be maintained for the abbreviated account.

The summary is an optional summary array in the description’s JSON metadata, with one nonempty text string per bullet. An omitted or empty array means no summary. Loading and CLI inspection return it with the description, including at historical revisions. Validation rejects malformed bullets while keeping the full Markdown readable as a draft. Summary edits use the same file snapshots and affected-description review as other metadata edits.
