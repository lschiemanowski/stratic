# Reading test evidence and project problems

The reader lets a person inspect the evidence and mechanical problems associated with a project while descriptions are still being edited. This supports review without requiring the desktop to become a test runner or to prevent all incomplete intermediate states.

The Tests view displays cataloged tests and their recorded individual outcomes. Each card can open the test’s source or the description passage it checks. Results are labeled according to whether they apply to the viewed content or an earlier snapshot; a test with no individual result is shown as unrecorded rather than inferred to pass from an aggregate result.

For example, a test may have passed before a description edit, but its record still names the older content tree. The view keeps that pass visible as earlier evidence. The label does not mean the test now fails, and opening the card does not rerun it. The person or agent decides what fresh verification the change requires.

The Problems view lists issues discovered while loading the project, including malformed metadata, invalid hierarchy, and broken passage links. Where an issue identifies a description, it can be opened for inspection. Descriptions also expose their own connection problems, so a reader can find the affected prose directly.

Tests and problems answer different questions. A clean Problems view means the recorded structure and links resolve. A passing test reports an observed execution. Neither by itself establishes that the account of the program is complete or accurate.
